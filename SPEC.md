## 1. Цель

Одна конверсия: человек пишет в **WhatsApp** (основной канал) или **Telegram** (второй), и текст сообщения уже заполнен: со страницы услуги, из брифа или из конструктора тренинга.
Сайт сам служит доказательством уровня: на каждой странице услуги есть живое демо.

Метрики (Yandex Metrica, цели): клик WhatsApp, клик Telegram, завершённый бриф, взаимодействие с каждым демо.

## 8. Демо и их сценарии

Все демо — клиентские симуляции на моках, без реальных API и ПДн; грузятся лениво при прокрутке; пауза вне экрана; при reduced motion — статичный постер/ролик; работают с клавиатуры.

| Страница | Демо | Сценарий |
|---|---|---|
| Сайты | **«Рентген»** | Переключатель накладывает на эту же страницу сетку, токены и имена компонентов; панель показывает **измеренные в вашем браузере** LCP, CLS и вес JS (PerformanceObserver). Второй переключатель «Человек / Машина» показывает `.md`-версию страницы |
| Mini Apps | **Мини-апп в телефоне** | Direct link не настроен `[факт]`, поэтому: демо-сборка `/demo/miniapp` на моке Telegram-окружения, сценарий **«кофейня»**: каталог → карточка → корзина → заказ → экран «заказ принят» (подпись «демо-сценарий»). Рядом блок «Собственный продукт: @elazart_bot, обучающий бот по ИИ» + QR на бота. Mobile: кнопка «Открыть @elazart_bot» + короткий ролик демо |
| Боты | **Симулятор чата** | Сценарий **«автосервис»** из `content/demos/bot.ts`: /start → меню (услуги, цены, запись) → выбор услуги и времени → номер (фейковый, подставляется кнопкой) → «Заявка принята» → рядом второй экран «уведомление менеджеру». Подпись «демо-сценарий» |
| Автоматизация | **«До → после»** (GSAP ScrollTrigger) | Ручной процесс: заявка в WhatsApp → копирование в таблицу → менеджер → ответ. При прокрутке превращается в поток узлов: заявка → AI-разбор → таблица/CRM → уведомление → ответ клиенту. Цифры времени только с пометкой «пример», из content.
